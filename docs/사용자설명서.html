개요와 범위

무엇을 하는 도구이고, 무엇을 하지 않는지 먼저 정리합니다.

HC LIVE는 편성한 내용을 끊김 없이 재생하는 것까지를 책임집니다. 인코딩과 실제 송출은 OBS나 vMix가 담당하고, HC LIVE는 그들에게 깨끗한 화면을 공급합니다. 모니터에 직접 띄우는 것도 가능합니다.

소스 HC LIVE 출력 로컬 파일 ┐ ┌ 모니터 (최종 화면) 지정 폴더 ├→ 편성 → 무결절 재생 → 출력창 ─┤ 유튜브 │ └ OBS·vMix → 유튜브 라이브 Cloudflare │ Bunny ┘

하는 일

  • 여러 출처의 영상을 하나의 라이브러리로 묶습니다
  • 요일·시간대 단위로 편성하고, 나머지 시간은 자동으로 채웁니다
  • 항목 전환 시 검은 화면이 나가지 않습니다
  • 채널을 여러 개 동시에, 각각 다른 편성으로 운영합니다
  • 사람 없이 24시간 돌아갑니다

하지 않는 일

  • 인코딩·트랜스코딩 — OBS/vMix가 합니다
  • 직접 RTMP 송출 — 스트리밍 출력은 OBS/vMix에 위임합니다
  • 영상 편집 — 컷 편집, 자막 렌더링, 합성은 다루지 않습니다
  • 시청자 전송(CDN) 운영 — 별도 컴포넌트의 영역입니다
CDMB CMS와의 차이

CMS는 전광판·매장 TV 같은 디스플레이를 관리하는 제품입니다. HC LIVE는 편성을 방송하는 제품입니다. HC LIVE의 모니터 출력은 같은 PC에 연결된 로컬 모니터만 대상으로 하며, 원격지 디스플레이 관리·밝기 제어· 포스터 우선송출 같은 사이니지 기능은 다루지 않습니다.

설치

npm install
npm run clips     # 검증용 테스트 클립 생성 (선택)
npm run app       # 앱 실행

실행하면 관리 창이 열리고, 로컬 서버가 127.0.0.1:4200에서 시작합니다. 포트가 이미 쓰이고 있으면 자동으로 다음 포트를 찾습니다.

기동 실패는 조용히 넘어가지 않습니다

서버를 시작하지 못하면 오류 창을 띄우고 앱이 종료됩니다. 앱은 떠 있는데 방송은 안 나가는 상태를 만들지 않기 위한 것입니다.

첫 편성까지

  1. 영상 넣기 — media/ 폴더 아래에 영상 파일을 둡니다. 하위 폴더는 그대로 소스 그룹이 됩니다.
  2. 라이브러리 스캔 — 관리 화면 우측 상단 라이브러리 스캔. 길이·해상도를 실측해 목록에 올립니다.
  3. 블록 배치 — 주간 편성 탭에서 빈 시간을 세로로 끌어 블록을 만들고, 소스 그룹·요일·시간대를 정합니다.
  4. 자동 채움 — 나머지 시간 자동 채움을 눌러 24시간을 완성합니다.
  5. 런다운 생성 — 편성 규칙이 그날의 재생 목록으로 만들어집니다.
  6. 출력창 열기 — 출력 탭에서 모니터를 배정하거나 창 캡처 출력을 추가합니다.

화면 구성

관리 화면은 세 개의 탭으로 나뉩니다. 편성의 흐름을 그대로 따릅니다.

탭다루는 것단위
주간 편성편성 블록 배치 + 자동 채움요일 × 시간대 (규칙)
런다운생성된 하루치 재생 목록, 미세 조정항목 (실행)
출력모니터 배정, 해상도·스케일·오디오출력

좌측은 라이브러리와 소스 연결, 우측은 전환 계측입니다. 계측은 전환이 얼마나 매끄러웠는지를 실시간으로 보여줍니다 — 자세한 읽는 법은 8장에 있습니다.

왜 그리드와 리스트가 나뉘어 있나

주간 편성은 반복되는 규칙이라 요일 × 시간 격자가 맞습니다. 런다운은 하루 수백~수천 항목이라 시간 축에 배치하면 짧은 항목이 몇 픽셀이 되어 다룰 수 없습니다. 그래서 목록입니다. 규칙은 그리드에서 놓고, 결과는 목록에서 확인합니다.

필러가 필요한 상황은 대개 네트워크 장애입니다. 그때 클라우드에 있는 필러는 정작 쓸 수 없습니다. 필러 후보는 로컬 항목으로만 잡습니다.

이 Cloudflare 계정은 CDMB CMS와 공용입니다. CMS의 설명서 영상이 같은 계정에 creator=cms 또는 creator 없이 들어 있습니다. creator를 비우고 동기화하면 CMS 영상 42건이 라이브러리에 딸려 들어오고, 자동 채움을 돌리면 그대로 방송에 나갑니다.

HC LIVE는 creator=hcjoynLive를 씁니다. 영상을 업로드할 때도 이 값을 지정해야 목록에 잡힙니다.

인코딩 중인 영상은 재생되지 않습니다. Bunny의 status가 4(완료)가 되기 전에는 HLS 주소가 403을 돌려줍니다. 목록에는 준비 중으로 표시됩니다.

서버에서 curl로 확인하면 403이 납니다. Bunny 풀존이 레퍼러 없는 요청을 차단하기 때문입니다. 브라우저는 레퍼러를 보내므로 실제 재생은 정상입니다 — 이것을 재생 불가로 오인하지 마세요.

자격증명 보관

입력한 값은 data/credentials.json에만 저장되며 저장소에 올라가지 않습니다. 조회 API는 설정 여부만 돌려주고 값 자체는 절대 내보내지 않습니다. 화면에 입력한 내용도 저장 후 지워집니다.

편성하기

편성은 세 단계입니다. 손으로 하는 것은 1단계뿐이고, 나머지는 버튼 하나입니다.

1. 편성 블록 어느 소스 그룹을 → 기간 × 요일(복수) × 시간대(복수)에 ↓ ← 운영자가 직접 하는 유일한 작업 2. 자동 채움 블록이 없는 나머지 모든 시간 ↓ ← 버튼 하나 3. 런다운 날짜별 실제 재생 목록. 시작 시각이 초 단위로 확정됨 ↓ 미세 조정 → 확정 · 송출

고정 시각 마커

"정시에 시작"은 실제로 세 가지 다른 의미입니다. 하나로 뭉뚱그리면 운영 중에 반드시 문제가 됩니다.

마커동작쓰는 상황
HARD그 시각에 재생 중인 항목을 끊고 시작 정시 뉴스, 계약 광고. 블록 시작에 자동 부여
SOFT앞 항목이 끝나기를 기다렸다가 시작 화면이 잘리는 게 더 나쁜 경우
NOT BEFORE그 시각 전에는 시작하지 않음 특정 시각 이후에만 나가야 하는 콘텐츠

Hard는 앞 항목을 자르므로 편집 화면에서 N초 잘림을 미리 경고합니다. Not Before는 공백을 만들 수 있어 필러를 제안합니다.

자동 채움

블록이 없는 모든 시간을 한 번에 채워 24시간 편성을 완성하는 단계입니다. 커버리지가 100%가 되어야 완성된 것입니다.

짧은 소재로 채우면 항목이 폭증합니다

11초짜리 클립으로 하루를 채우면 6,000개가 넘습니다. 생성 자체는 빠르지만 목록과 전송이 무거워집니다. 1,000개를 넘으면 경고가 뜹니다. 자동 채움 소재는 되도록 길게(1분 이상) 잡는 것을 권합니다.

런다운 조정

생성된 목록은 현재 지점부터 표시됩니다. 자정부터 그리면 화면 가득 과거만 보이고, 과거는 잠겨 있어 아무것도 할 수 없기 때문입니다.

  • 드래그로 순서 변경 — 놓는 즉시 이후 시작 시각이 다시 계산됩니다
  • 온에어 항목과 다음 1개는 잠깁니다 🔒 — 실수로 방송을 끊는 사고 방지
  • 항목마다 어느 블록에서 왔는지 표시됩니다. 문제가 생기면 블록으로 거슬러 올라갈 수 있습니다
  • 다시 생성은 블록 설정대로 새로 만듭니다. 손으로 고친 내용이 있으면 확인을 받습니다

채널과 출력

라이브러리는 전 채널이 공유하고, 편성·런다운·출력은 채널마다 독립입니다.

채널

채널은 독립된 하나의 송출 라인입니다. 자체 편성과 하나 이상의 출력을 가집니다. 한 채널이 장애로 재기동해도 다른 채널은 영향받지 않습니다.

출력 세 가지

유형최종 목적지제약
모니터 직출력연결된 모니터 = 최종 화면 물리 모니터가 실제로 연결돼 있어야 합니다. 최대 4대
창 캡처OBS·vMix가 캡처 → 인코딩 창 픽셀 수만큼의 실제 화면 공간이 필요합니다
NDIOBS·vMix가 수신 조건부 기능 — 화면 공간이 부족할 때. 아직 미구현

조합할 수 있습니다. 한 채널이 창 캡처(OBS용) + 모니터 두 대를 동시에 가질 수 있습니다.

모니터 배정

출력 탭의 배치도는 OS 디스플레이 설정과 같은 상대 위치·비율로 그려집니다. 모니터는 전역 자원이고 출력은 채널 소유입니다 — 한 모니터에는 출력 하나만 들어갑니다.

  • 빈 모니터 클릭 → 현재 채널에 배정. 해상도는 자동 감지
  • 다른 채널이 쓰는 모니터 → 확인을 받고 가져옵니다. 조용히 뺏지 않습니다
  • 연결 끊김 → 해당 출력만 멈추고, 재연결하면 자동 복귀합니다

오디오

채널당 하나만 소리를 냅니다

같은 채널을 여러 모니터에 띄우면 각 출력이 같은 내용을 재생하므로, 그대로 두면 소리가 겹쳐 에코가 납니다. 오디오는 라디오 버튼처럼 동작해서 하나를 켜면 나머지는 자동 음소거됩니다. 담당 출력이 내려가면 다음 출력이 승계합니다.

채널이 두 개 이상이면 전용 오디오 장치가 필요합니다. 시스템 기본 출력으로는 모든 채널이 한 버스에 섞여 분리할 수 없습니다. macOS는 BlackHole, Windows는 VB-Cable 같은 가상 오디오 드라이버를 쓰며, 앱은 장치 부족을 감지해 안내만 하고 설치하지는 않습니다.

부하 안내

부하의 단위는 채널이 아니라 출력입니다. 채널이 하나여도 모니터 3대에 미러하면 디코딩이 3개입니다. 출력을 3개 이상 추가하면 OS 디스플레이 미러링 안내가 뜹니다 — 같은 화면을 여러 모니터에 띄우는 것이 목적이라면 그쪽이 디코딩 1회로 끝납니다.

송출 연결

OBS 창 캡처

  1. HC LIVE에서 창 캡처 유형 출력을 추가합니다.
  2. OBS에서 소스 추가 → 화면 캡처(macOS) 또는 윈도우 캡처(Windows).
  3. 창 목록에서 HC LIVE — 출력을 고릅니다. 채널마다 창이 하나씩 있습니다.
  4. OBS 캔버스 해상도를 출력창 해상도와 맞춥니다.
해상도는 화면 배율의 영향을 받습니다

창 크기는 논리 포인트지만 OBS는 물리 픽셀을 캡처합니다. Retina(배율 2) 화면에서 논리 960×540 창은 OBS에서 1920×1080으로 잡힙니다. HC LIVE는 요청 해상도를 화면 배율로 나눠 창을 만들기 때문에, 1920×1080을 지정하면 OBS에서도 1920×1080으로 들어옵니다.

이 처리가 없으면 Retina에서 1920 요청이 3840×2160 캡처가 되어 의도치 않은 4K 부하가 걸립니다.

유튜브 라이브

기본 전송처는 유튜브 라이브입니다. 전송비가 들지 않고 도달이 가장 넓습니다. HC LIVE → OBS → RTMP → 유튜브 순서이며, HC LIVE는 OBS까지만 책임집니다.

자체 전송(CDN)이 필요해지는 계기는 대개 셋입니다 — 플랫폼 리스크가 현실화될 때, 접근 권한 제어가 필요할 때, 광고·브랜딩을 완전히 통제해야 할 때. 그때는 OBS 다중 출력으로 유튜브와 자체 채널을 동시에 내보낼 수 있습니다.

콘텐츠 정책

본인 소유 콘텐츠만

유튜브 소스는 OAuth로 인증한 본인 채널의 영상·재생목록만 등록할 수 있습니다. 임의의 유튜브 URL 붙여넣기는 구현하지 않았습니다. Cloudflare·Bunny도 본인 계정의 라이브러리만 연결합니다. 저작권과 각 서비스 이용약관 준수를 위한 것이며 기능 편의를 이유로 완화하지 않습니다.

무인 운영

자동 시작

앱 안에서 열리는 출력창은 사람의 클릭 없이 재생을 시작합니다. 무인 운영에서 사람이 버튼을 눌러줘야 한다면 그건 무인이 아니기 때문입니다. 24시간 채널은 언제 시작하든 지금 나가야 할 지점부터 나갑니다.

대기 화면

편성이 비어 있거나 복구 중일 때는 로고가 나갑니다. 검은 화면은 쓰지 않습니다 — 모니터에서는 장비 고장으로 오인되고, OBS에서는 신호 유실과 구분되지 않기 때문입니다.

로고는 설정에서 등록하며, 등록 전에는 앱 내장 로고가 나갑니다. 대기 화면 진입은 계획된 공백과 장애를 구분해 기록합니다.

무결절 재생 엔진

이 제품의 핵심입니다. 원리는 단순합니다.

  1. 비디오 레이어를 두 개(A/B) 두고 한쪽만 앞에 둡니다.
  2. A가 재생 중일 때 다음 항목을 B에 미리 로드하고 첫 프레임까지 디코드시켜 둡니다.
  3. 전환 직전 B를 아주 느린 배속으로 미리 돌려 재생 파이프라인을 깨웁니다(프리롤).
  4. A의 종료 지점에서 같은 태스크 안에서 B를 앞으로 보내고 A를 뒤로 보냅니다.

화면은 A의 마지막 프레임에서 B의 첫 프레임으로 바뀝니다. 검은 프레임이 낄 자리가 없습니다. 무결절의 실제 보장은 대기 레이어가 준비되지 않으면 전환 자체를 거부하는 데 있습니다.

전환 시점 판정

두 경로를 함께 씁니다.

경로역할
타이머남은 시간에 맞춰 예약. 반드시 발화하는 보장 경로
프레임 콜백매 표시 프레임마다 확인. 프레임 단위로 정확하지만 창이 가려지면 멈춤
왜 두 경로인가

초기 구현은 프레임 콜백만 썼는데, 렌더링이 억제되는 환경에서 전환이 30초까지 밀렸습니다. 정밀도를 위한 장치가 정확성의 단일 실패점이 되어서는 안 됩니다. 실제로 40분 무인 운전에서 프레임 콜백이 한 번도 불리지 않았는데도 전환 200건이 모두 정상이었습니다.

문제 해결

증상원인과 조치
앱은 떴는데 창이 안 열림 서버 기동 실패입니다. 오류 창의 내용을 확인하세요. 다른 인스턴스가 이미 실행 중일 수 있습니다.
라이브러리에 영상이 안 보임 ffprobe를 찾지 못하면 길이를 읽을 수 없어 길이 없음으로 표시됩니다. FFPROBE_PATH를 지정하세요.
Cloudflare 목록이 비어 있음 creator 값이 실제 영상의 creator와 다릅니다. 업로드 시 지정했는지 확인하세요. 비우지는 마세요 — CMS 영상이 딸려 옵니다.
Bunny 영상이 재생 안 됨 인코딩이 끝나지 않았을 수 있습니다(준비 중). 서버에서 curl로 403이 나오는 것은 정상입니다 — 브라우저에서는 재생됩니다.
편성에 공백이 생김 자동 채움이 꺼져 있거나 소재가 부족합니다. 런다운의 경고 행에서 바로 채울 수 있습니다.
계측이 "계측 불가" 출력창이 가려져 있습니다. 재생은 정상입니다.
OBS 캡처 해상도가 두 배 화면 배율 문제입니다. HC LIVE가 자동 보정하지만, 출력창을 수동으로 만들었다면 요청 해상도를 배율로 나눠 지정하세요.
여러 모니터에서 소리가 겹침 오디오 담당이 둘 이상일 수 없지만, 채널이 여럿이면 시스템 기본 출력에서 섞입니다. 전용 오디오 장치를 쓰세요.
런다운 항목이 너무 많음 자동 채움 소재가 짧습니다. 1분 이상 소재를 쓰거나 블록으로 시간을 더 채우세요.
